# 21 · кошелёк района — TON Connect 2.0

Мини-приложение для донатов в фонд района: подключение кошелька через **TON Connect 2.0**,
живой баланс, отправка TON с комментарием, история и статистика сборов.

Стек: **React 19 + TypeScript + Vite**, `@tonconnect/ui-react`, данные — **tonapi.io**.
Тёмная тема в стиле Telegram, вёрстка под мобильный WebApp.

---

## Быстрый старт

```bash
cd wallet-app
npm install
npm run dev          # → http://localhost:5173
```

Сборка и локальный просмотр продакшен-версии:

```bash
npm run build        # → dist/
npm run preview      # → http://localhost:4173
```

Проверка типов и тесты:

```bash
npx tsc --noEmit             # типы
node scripts/verify-cell.mjs # BOC-энкодер vs эталонный @ton/core
node scripts/logic-test.mjs  # разбор ответов tonapi, суммы, ошибки
node scripts/render-test.mjs # рендер компонентов
```

### Как это работает

**Подключение.** `TonConnectUIProvider` в `main.tsx` поднимает TON Connect на всё
приложение; кнопка — штатная `<TonConnectButton />`. Адрес берём из `useTonAddress()`
и дублируем в `localStorage`, чтобы при повторном открытии сразу показать баланс,
а не мигать состоянием «не подключён», пока восстанавливается сессия.

**Баланс.** `useBalance` опрашивает `GET /v2/accounts/{address}` раз в 5 секунд.
Опрос встаёт на паузу, когда вкладка скрыта, и возобновляется при возврате.
Каждый новый запрос отменяет предыдущий через `AbortController` — медленный ответ
не перезапишет более свежий. При ошибке прошлое значение остаётся на экране.

**Донат.** `useDonate` собирает транзакцию и шлёт через `tonConnectUI.sendTransaction`.
Комментарий кодируется в payload как text comment (32 нулевых бита + UTF-8) —
это делает `lib/cell.ts`, свой мини-энкодер BOC вместо тяжёлого `@ton/core`.
Его вывод побайтово сверен с эталонной библиотекой (`scripts/verify-cell.mjs`).

**История и статистика.** `useDonations` тянет последние 100 транзакций и
оставляет только входящие переводы с ненулевой суммой и известным отправителем —
это отсекает служебные сообщения. Показываем 10 последних, а «собрано» и
«донатеров» считаем по всей выборке.

## Настройка

Все параметры — через `.env` (см. `.env.example`), править код не нужно:

| Переменная | Назначение |
|---|---|
| `VITE_FUND_ADDRESS` | адрес фонда — получатель донатов |
| `VITE_MANIFEST_URL` | URL манифеста, если он на другом домене |
| `VITE_TONAPI_BASE` | база API; `/tonapi` — ходить через прокси |
| `VITE_TONAPI_KEY` | ключ tonapi (**попадает в бандл** — только для локальной разработки) |
| `VITE_TWA_RETURN_URL` | куда вернуть пользователя после кошелька |

### Манифест TON Connect — обязательный шаг

Кошелёк скачивает манифест сам, и **домен в нём должен совпадать с доменом
приложения**, иначе подключение будет отклонено. Перед деплоем отредактируйте
`public/tonconnect-manifest.json`:

```json
{
  "name": "21 · кошелёк района",
  "url": "https://ВАШ-ДОМЕН/",
  "iconUrl": "https://ВАШ-ДОМЕН/assets/logo.png"
}
```

Файл должен отдаваться публично, по HTTPS и с `Access-Control-Allow-Origin: *`.

### Лимиты tonapi

По умолчанию запросы идут прямо на `https://tonapi.io` (CORS разрешён), ключ не нужен —
этого хватает для нескольких пользователей. При росте нагрузки возьмите ключ на
[tonconsole.com](https://tonconsole.com) и **не кладите его в бандл**: поднимите прокси
и укажите `VITE_TONAPI_BASE=/tonapi`. Dev-прокси уже описан в `vite.config.ts` и
подставляет `TONAPI_KEY` из окружения:

```bash
TONAPI_KEY=xxx npm run dev
```

## Деплой

### GitHub Pages (подпуть)

`base: './'` уже задан, поэтому сборка работает из любой вложенной папки.

```bash
npm run build
# скопировать содержимое dist/ в папку публикации, например /wallet
```

В манифесте укажите полный URL с подпутём: `https://USER.github.io/21app/wallet/`.

### Свой node-хост

`dist/` — статика, отдавайте любым сервером. Главное — чтобы
`/tonconnect-manifest.json` был доступен публично.

### Telegram Mini App

1. Разместите сборку по HTTPS.
2. В **@BotFather** → `/newapp` (или `/setmenubutton`) укажите URL приложения.
3. Проверьте `VITE_TWA_RETURN_URL` — по нему кошелёк вернёт пользователя в мини-апп.

## Что проверено

Автотесты в `scripts/`:

- **BOC-энкодер** — 10 случаев, включая пустую строку, кириллицу, эмодзи и строки
  длиннее одной ячейки (127/128/500 байт, многоуровневая вложенность). Вывод
  совпадает с `@ton/core` побайтово.
- **Логика** — 25 проверок: арифметика на `bigint` без потери точности,
  парсинг ввода (запятая, обрезка >9 знаков, мусор), фильтрация транзакций
  (external-сообщения, нулевые суммы, неуспешные), подсчёт уникальных донатеров,
  обработка 429 и обрыва сети.
- **Рендер** — 13 проверок разметки: суммы, склонения, метка «вы», состояние
  «Подтвердите в кошельке» с блокировкой кнопки, тосты.

Не проверено вживую и требует вашей проверки на боевом домене: реальное подключение
кошелька и отправка транзакции — для этого нужны Telegram-клиент и настоящий
Tonkeeper, которых нет в среде разработки.
