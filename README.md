# 21 — районная сеть (Telegram Mini App)

Одностраничное веб-приложение: городская ОС района в формате **Telegram Mini App**.
Стиль: чистый мобильный интерфейс + пиксель-арт в палитре белый / чёрный / серые / `#d4a373`.

## Запуск

```bash
# любой статический сервер
python3 -m http.server 8080
# или точка входа для node-хостинга (без зависимостей, порт — env PORT, по умолчанию 8080)
node http-wrapper.js
# → http://localhost:8080  (кнопка «Войти как разработчик» — полный проход без Telegram)
```

`http-wrapper.js` — минимальный статический сервер (node:http, без npm-зависимостей):
MIME-типы, `Cache-Control` для assets, SPA-фолбэк, защита от path traversal.
`sw.js` безопасен под Node (guard: исполняется только в worker-контексте).

GitHub Pages: включить на репозитории из корня. Для входа через Telegram домен нужно
привязать к боту через **@BotFather → /setdomain** (иначе на гейте «Bot domain invalid»).

## Состав

| Файл | Что |
|---|---|
| `index.html` | Всё приложение: CSS + JS внутри (единый файл) |
| `assets/` | PNG/GIF пиксель-заглушки (имена стабильны — заменяются без правки кода) |
| `http-wrapper.js` | Точка входа для node-хостинга: `node http-wrapper.js` (PORT из env) |
| `sw.js` | Service worker: офлайн-кэш, автообновление (guard под Node) |
| `manifest.webmanifest` | PWA-манифест (белая тема) |
| `tonconnect-manifest.json` | Манифест TON Connect (статика для GitHub Pages; node-хост отдаёт свой, под фактический origin) |
| `assets/vendor/tonconnect-ui.min.js` | TON Connect UI SDK (вендорится локально, без CDN) |
| `tools/qr.js` | QR-кодер (byte mode, EC L, v1–5) — вшит в `index.html` между `/*QR:BEGIN*/…/*QR:END*/` |
| `tools/gen_assets.py` | Генератор пиксель-арт заглушек: `python3 tools/gen_assets.py` |

## Что внутри

- **Вход через Telegram**: имя, ник, аватар (→ пиксель 16×16) из WebApp SDK;
  вне Telegram — гейт «Войти как разработчик» (dev-режим с админ-панелью).
- **Онбординг**: 3 экрана (сосед / как это работает / профиль).
- **Карта района** — Яндекс.Карты: пины квест (синий) / проблема (красный) / решено (серый),
  легенда, статистика, список точек рядом; без сети — пиксель-карта с фолбэк-маркерами.
- **Задачи двора** — типы: починить / помочь / обмен / мастер-класс.
  Взять → в работе → сдать: +XP, +карма, +₽; архив с чипами «решена/твоя».
  «Сообщить о проблеме»: заявка с фото (→ пиксель-арт) и точкой → **на модерацию**, +5 XP +3 кармы.
- **Фонд района** — общий банк, цель квартала, вклады, проекты со срочностью,
  **AI-распределение** (срочность × дефицит × близость к финишу), журнал, последняя раздача.
- **Суд соседей** — голос с весом по карме (1 + карма/50), кворум 12, дела с 2–3 вариантами.
- **Знания** — вода / энергия / еда / ремонт: карточки с цифрами и инфографикой, +3 XP за прочтение.
- **Профиль** — голова (4) + тело (3) + цвет + своё фото (→ пиксель 16×16), статистика,
  прогресс, 8 достижений, выход.
- **Стикер с QR** — canvas: лого 21, QR (глубокая ссылка `…#q={id}` / `…#u={id}`),
  «СКАНИРУЙ · ВОЗЬМИ · СДЕЛАЙ»; печать 60 мм (ч/б), поделиться, скачать PNG.
  QR шифруется внутренним кодером (в `index.html`), декодируется сканерами.
- **Админ-панель** (dev) — модерация заявок (одобрить → точка на карте / отклонить),
  точки, посты в ленту, дела в суд, проекты в фонд, управление лентой.

## Бот: модерация и админ (токен — только в env бот-хоста)

Telegram-бот (`@twentyonemovementbot`) — **единственный канал админ-функций**:

- заявка «Сообщить о проблеме» → бот присылает админу сообщение (ник, тип, детали, точка, ID);
- действия админа (одобрение/отклонение, новые точки, посты, дела, проекты, AI-раздача,
  вклады, голоса суда) → уходят боту; при недоступности релея событие становится в
  локальную очередь (`st.bot.queue`, до 50) и досылается при связи;
- Chat ID настраивается в админ-панели: вручную или кнопкой «Найти мой чат»
  (отправить боту `/start` → кнопка поднимет чат через `getUpdates`).

Chat ID админа по умолчанию зашит в код: `ADMIN_CHAT = 1896036065` (в `index.html`).
Панель показывает текущий id; пусто = вернуть чат админа, `0` = отключить отправки.

Токена в клиентском коде НЕТ. Приложение ходит в `POST <base>/<метод>` (только белый
список методов), где `<base>` = `window.OS21_BOT_API` (файл `config.js`, см.
`config.example.txt`) или `/api/bot` на том же origin. Релей реализован в `http-wrapper.js`:

```bash
# на бот-хосте — токен только здесь:
TELEGRAM_BOT_TOKEN='123:ABC...' PORT=8080 node http-wrapper.js
# опции: BOT_ALLOW_ORIGIN='https://owner.github.io' (CORS для чужого фронтенда),
#        BOT_TOKEN (алиас). Методы: getMe, sendMessage, getUpdates, setMyCommands,
#        deleteWebhook, getWebhookInfo — остальные 400.
```

На GitHub Pages (без своего хоста) можно не поднимать релей: тогда положите `config.js`
в корень с `window.OS21_BOT_API` на ваш бот-хост. `config.js` в `.gitignore`.

### Деплой на node-хостинг (бот-хост)

Точка входа зафиксирована в `package.json` (`npm start` → `node http-wrapper.js`).
Переменные окружения:

| env | что |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота — только здесь, в коде клиента его нет |
| `TONAPI_KEY` | ключ [tonapi.io](https://tonconsole.com) для релея `/api/tonapi` — тоже только здесь |
| `TONAPI_BASE` | база TON API (по умолчанию `https://tonapi.io`) |
| `PORT` | порт (хостинги отдают свой) |
| `BOT_ALLOW_ORIGIN` | CORS для чужого фронтенда (по умолчанию `*`) |

### Переменные в панели хостинга (приоритетный способ)

Если переменные заданы в панели бот-хоста (Amvera, Railway, Render и т.п.) —
**файл `.env` создавать не нужно**. Значения из окружения имеют приоритет и
`.env` их не перезатирает, так что можно спокойно держать оба варианта:
панель для прода, файл для локальной разработки.

Обязательный минимум в панели: `TELEGRAM_BOT_TOKEN` и `TONAPI_KEY`.
`PORT` почти всегда подставляет сам хостинг — **не задавайте его вручную**,
иначе приложение может встать не на тот порт, который слушает балансировщик.

> **Одна команда запуска.** Хостинг должен стартовать только `npm start`
> (то же самое, что `node http-wrapper.js`). Если одновременно заданы и
> `CMD` в Dockerfile, и команда в панели — приложение поднимется дважды и
> второй процесс упадёт с `EADDRINUSE: address already in use`.

### Настройка через `.env`

Сервер читает файл `.env` рядом с `http-wrapper.js` — токены не нужно
передавать флагами в командной строке (и они не попадут в history шелла):

```bash
cp .env.example .env     # шаблон со всеми переменными и пояснениями
# вписать реальные значения в .env
node http-wrapper.js     # .env подхватится сам
```

`.env` в `.gitignore` — в репозиторий он не попадёт. Коммитить можно только
`.env.example` (в нём заглушки). Переменные из окружения хостинга имеют
приоритет над файлом, поэтому на проде их удобнее задавать в панели хостинга.

> Если токен всё же попал в Git или в переписку — считайте его скомпрометированным:
> отзовите бот-токен через `@BotFather → /revoke`, ключ tonapi — в кабинете
> [tonconsole.com](https://tonconsole.com). Удаления файла недостаточно: он
> остаётся в истории коммитов.

## Админ-панель в боте

Управление районом идёт из Telegram — команда `/start` боту. Панель видит
только владелец `ADMIN_ID`, остальным бот отвечает нейтральной заглушкой.

```bash
TELEGRAM_BOT_TOKEN='...' ADMIN_ID='1896036065' node http-wrapper.js
```

Что умеет:

| Раздел | Действия |
|---|---|
| Задания | создать (пошагово: категория → название → описание → цена → координаты), изменить название/описание/цену/координаты, скрыть/опубликовать, закрыть, удалить (с подтверждением) |
| Заявки | принять, принять со своей ценой, отклонить, отклонить + заблокировать автора |
| Цены | своя цена для каждой категории — подставляется в новые задания |
| Блеклист | заблокировать по id или из заявки, разблокировать, `/block id причина`, `/unblock id` |
| Сводка | счётчики заданий, заявок, блеклиста, сумма обещанного из фонда |
| Журнал | последние 15 действий админа |

Новая заявка из приложения сразу приходит админу **с кнопками решения** —
принять или отклонить можно прямо из уведомления, не открывая панель.

### Общее хранилище

Раньше всё состояние жило в `localStorage` браузера, поэтому созданное админом
видел только он сам. Теперь задания, заявки, цены и блеклист лежат в одном
JSON-файле на сервере (`DATA_FILE`, по умолчанию `data/board.json`), а
приложение читает их через `/api/board` и обновляет раз в 30 секунд.

Каталог `data/` в `.gitignore` — данные района не попадают в репозиторий.
На хостинге он должен быть на **постоянном диске**, иначе задания пропадут
при передеплое.

> **Один потребитель getUpdates.** Telegram отдаёт апдейты только одному
> читателю. Поэтому приложение больше не вызывает `getUpdates` напрямую —
> кнопка «найти чат» ходит в `/api/admin/recent-chats`. Если запустить бота
> дважды, второй экземпляр получит 409 и уйдёт в паузу — в логе будет видно.

### Релей TON API: `GET /api/tonapi/<путь>`

Кошелёк района (`wallet-app/`) читает баланс и транзакции через этот релей,
чтобы ключ не попадал в браузер:

```bash
TELEGRAM_BOT_TOKEN='123:ABC...' TONAPI_KEY='ваш-ключ' PORT=8080 node http-wrapper.js
```

Разрешены только `v2/accounts/{addr}` и `v2/blockchain/accounts/{addr}/transactions`
(остальное → 400, чтобы релей не стал открытым прокси); из query проходит только
`limit`. Ответы кешируются на 4 секунды, при недоступности tonapi отдаётся
последний удачный (`X-Cache: STALE`). Без `TONAPI_KEY` работает на бесплатном лимите.

Хостинг должен запускать **`npm start`** (из `package.json`). На случай автодетекта
«первого .js» в корне добавлен шим `index.js` (он просто требует `http-wrapper.js`), а
`config.example` намеренно лежит как `.txt`. Корневые `.js`: `index.js`, `http-wrapper.js`,
`sw.js` — все безопасны как точка входа.

## Кошелёк · TON Connect

Подключение кошелька — SDK `assets/vendor/tonconnect-ui.min.js` (локально, без CDN),
точка входа в UI: **Профиль → «👛 Подключить кошелёк · TON Connect»**.

- Подключение открывает модалку выбора кошелька (`openModal()`) и ждёт `onStatusChange`;
  адрес сохраняется в `st.user.ton` в user-friendly виде (`UQ…`), сырой — в `st.user.tonRaw`,
  сеть — в `tonChain` (`-239` mainnet / `-3` testnet), имя кошелька — в `tonWallet`.
- Пока адрес получен из кошелька, поле ввода только для чтения; правка руками — после «отключить».
- Сессия восстанавливается при следующем открытии (`connectionRestored`), повторно логиниться не нужно.
- Переводы (`Фонд → Внести`, TON-депозит кошелька выплат) идут через `sendTransaction`;
  `validUntil` — UNIX-время **в секундах** (мс кошельки отвергают как просроченную транзакцию).
- Если SDK не загрузился — фолбэк: адрес фонда с кнопкой «копировать» и ручной перевод.

**Манифест.** Кошельки требуют публичный `tonconnect-manifest.json`, домен в нём должен совпадать
с доменом приложения. Клиент берёт манифест рядом с `index.html` (работает и в корне, и на подпути
GitHub Pages `/21app/`); переопределить можно через `window.OS21_TON_MANIFEST` в `config.js`.
`http-wrapper.js` генерирует манифест на лету под фактический `Host`, статический
`tonconnect-manifest.json` в корне нужен для GitHub Pages — **укажите там свой домен**, если форкаете.

## Данные

- Все данные — `localStorage` (ключ `os21_v4`): пользователь, квесты, фонд, суд, лента,
  знания, бейджи; сброс — очистить хранилище.
- Шрифты системные (как в Telegram), без внешних зависимостей.
- Пикселизация: любые загруженные фото → палитра приложения (тёплые пиксели → `#d4a373`,
  остальное → 9 градаций серого).
